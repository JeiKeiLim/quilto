## Challenges and Issues

### 1. Context Building vs Storage Pruning Mismatch

**Storage Pruning (SMART):**
- Uses "first + recent" strategy
- Parameterized via `SessionConfig.max_conversation_turns`
- Keeps first turn + last (N-1) turns

**Context Building (HARDCODED):**
- Uses only last 4 turns
- Hardcoded, not parameterized
- Loses first turn after 4+ turns

**User Feedback Evidence:**
- Query: "What did I ask for the first time?"
- Expected: Original upperbody strength question
- Got: "Can you give me workout plan in detail?" (last query)
- Feedback: "it does have session context but only the last one"

### 2. Multi-Clarification Context Loss
With 4-turn limit, after 2 clarification rounds the original query drops out of context.

| Turn | Content |
|------|---------|
| 1 | User: vague query |
| 2 | Agent: clarification Q1 |
| 3 | User: answer 1 |
| 4 | Agent: clarification Q2 |
| 5 | User: answer 2 ← **Turn 1 drops out here** |

## Key Learnings

1. **Context building and storage pruning should use the same strategy** - Storage is smart (first + recent), context building is dumb (last N only)

2. **Multi-turn sessions require dedicated testing** - 2-3 turn tests don't catch context truncation issues

3. **Dual dogfooding is essential** - User manual feedback caught issues automated tests missed

4. **Mid-epic story addition is okay** - Story 20.5 was added after 20.4 revealed a gap; this is the feedback loop working correctly

5. **Investigation before implementation** - Stories 20.1 and 20.2 verified code worked before attempting fixes
