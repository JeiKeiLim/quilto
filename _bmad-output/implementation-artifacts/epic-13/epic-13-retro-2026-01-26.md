## Challenges and Issues Discovered

### 1. Retrieval Not Retrying on Insufficient Data
**Observation:** Retrieval appears to only be called once or twice. When Evaluator determines data is insufficient, there's no feedback loop to Retriever with expanded date ranges.

**Expected:** Evaluator → insufficient → Retriever retries with wider dates

**Status:** Gap in pipeline logic

### 2. Clarification Flow in Non-Interactive Mode
**Observation:** Story 13.4 implemented clarification routing, but in `non_interactive=True` mode (batch scripts), clarification questions are logged but don't block the flow.

**Resolution:** This is expected behavior for automated testing. Questions ARE captured in feedback records for analysis.

### 3. JSON Format Invalid Errors
**Observation:** JSON parse errors from LLM responses should trigger retries but may not be handled properly.

**Status:** Needs investigation - may be in LLM client layer

### 4. Global Context Never Updated (Observer Not Invoked)
**Observation:** The `logs/logs/context/` directory exists but is empty. Observer agent is never called.

**Evidence:**
- Observer agent exists in `packages/quilto/quilto/agents/observer.py`
- Trigger functions exist in `packages/quilto/quilto/state/observer_triggers.py`
- But Swealog's `execute_query_pipeline()` never imports or calls Observer

**Root Cause:** See Critical Architecture Issue below.

## 🚨 CRITICAL ARCHITECTURE ISSUE 🚨

### Issue: Quilto Framework Orchestration Design

**Summary:** Quilto currently provides individual agents but no orchestration layer. Applications (like Swealog) must manually import and wire all agents, defeating the purpose of a framework.

**Current State:**
```python
# Swealog's execute_query_pipeline() manually wires everything:
from quilto.agents import (
    RouterAgent, PlannerAgent, RetrieverAgent,
    AnalyzerAgent, SynthesizerAgent, EvaluatorAgent,
)
# ObserverAgent is NEVER imported or called
```

**Impact:**
- Observer agent exists but is never invoked → no personalization
- Retry loops not implemented → Evaluator can't trigger more retrieval
- Every Quilto application must duplicate ~300 lines of pipeline code
- New Quilto agents require manual integration in every application

**Expected Framework Behavior:**
```python
# What SHOULD happen:
from quilto import QueryPipeline
result = await pipeline.run(query)
# Observer, retries, everything automatic
```

**Decision Required:**
- Should Quilto provide complete pipeline orchestration (framework)?
- Or should Quilto remain a toolkit where apps build pipelines?
- This defines Quilto's public API

**Status:** BLOCKED - Requires dedicated architecture discussion session

**Owner:** Jongkuk Lim (Project Lead)

**Note:** This issue is beyond retrospective scope and deserves deep, focused discussion as it defines Quilto's public API and is the most important design decision in this project.

4. **Document decisions early** - The orchestration design should have been explicit from Epic 1.
