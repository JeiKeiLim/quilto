## Challenges and Issues Discovered

### 1. Story 16.2 Fix Was Incomplete
The cascade failure fix added fallback `analyzer_output`, but:
- Fallback uses string `"insufficient"` instead of `Verdict.INSUFFICIENT` enum
- With `strict=True`, Pydantic rejects strings for enum fields
- Same issue affects `query_type` field throughout orchestration

### 2. Type Ignore Comments Hiding Issues
```python
query_type=query_type,  # type: ignore[arg-type]
```
These comments suppressed warnings about type mismatches that became runtime errors.

### 3. LangGraph State Serialization
- `plan_node` stores `query_type` as string (`.value`)
- Downstream nodes receive string, not enum
- Models with `strict=True` reject the string

## 🚨 SIGNIFICANT DISCOVERY: Query Flow Still Broken

### Smoke Test Results

Command:
```bash
uv run swealog run --config ./llm-config-openai.yaml --storage ./logs --debug --non-interactive "How was my workout this week?"
```

**Observed Symptoms:**
- Response: `"I encountered an error: Synthesizer failed..."`
- Planner action: `expand_domain` (twice) then `clarify`
- Retriever: `0 entries` found
- Multiple ValidationError messages in debug output
- Analyzer, Synthesizer, Evaluator all fail with ValidationError

**Error Pattern:**
```
ValidationError: 1 validation error for AnalyzerInput
query_type
  Input should be an instance of QueryType [type=is_instance_of, input_value='insight', input_type=str]
```

### Hypotheses (Not Confirmed)

1. **Enum string coercion** - `strict=True` rejecting strings passed through state
2. **Empty retrieval** - 0 entries may trigger different failure path
3. **Cascade failure incomplete** - Story 16.2 may not cover all paths
4. **State serialization** - LangGraph state passing may lose type information

### What We Don't Know Yet

- Whether validation errors are the *cause* or just *symptoms*
- Why retriever returns 0 entries
- Whether Planner's `expand_domain` action works correctly
- Full agent output data (not visible in current debug)

### Recommendation

**Deep investigation required before Epic 17 dogfooding.**

This is out of scope for incremental fixes - requires dedicated research session to:
1. Add verbose logging to each agent node
2. Capture full input/output for each agent step
3. Test with known good data
4. Determine root cause vs symptoms

---

## Key Learnings

1. **`strict=True` and enum serialization need care** - passing enums through LangGraph state requires explicit conversion back to enum types

2. **`# type: ignore` comments hide real bugs** - they should be reviewed periodically, not accumulated

3. **Smoke testing reveals integration issues** - unit tests passed but e2e failed; need regular integration testing

4. **Clean architecture ≠ working architecture** - the CLI refactor is clean but orchestration issues remain

5. **Half-fixes create false confidence** - Story 16.2 appeared to fix the issue but didn't address enum serialization
