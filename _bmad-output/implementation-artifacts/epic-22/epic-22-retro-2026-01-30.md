## Challenges and Issues

### 1. CRITICAL: LOG Persistence Bug Discovered

**Problem:** LOG entries are not being saved to storage files.

**Evidence (from iter-011-pre user feedback):**
- `2026-01-30_4dd8c095.json`: "Even though all outputs look correct, I don't see 2026-01-21.md nor parsed json got created nor updated with log I provided."
- `2026-01-30_d265b1e8.json`: "this also did not create nor update actual files for both raw and parsed json."

**Impact:** Users log workouts thinking they're saved, but data is silently lost. Core Swealog functionality broken.

**Status:** UNFIXED - Added as Epic 23 critical priority.

### 2. Dogfooding Verification Gap

**Problem:** Dogfooding iterations verified intermediate outputs but not actual file system changes.

**Root Cause:** Scripts check that Parser returns correct output, but don't verify StorageRepository actually writes to disk.

**Resolution:** Added process improvement to verify file-level changes in all future dogfooding iterations.

## Key Learnings

1. **Verify file-level changes, not just intermediate outputs** - The LOG persistence bug went undetected because we only checked agent outputs, not actual storage writes.

2. **Defense-in-depth works** - Combining prompt instructions with runtime validation creates a robust system that catches LLM non-compliance.

3. **Validate before coding** - Story 22.4 saved effort by discovering existing implementation first.

4. **User feedback catches real bugs** - The LOG persistence issue was discovered through manual user testing, not automated tests.

## Dogfooding Verification Rules (NEW)

Every dogfooding iteration MUST verify file-level changes:

| Input Type | Required Verification |
|------------|----------------------|
| LOG | `logs/raw/YYYY/MM/YYYY-MM-DD.md` created/appended, `logs/parsed/*.json` updated |
| CORRECTION | Target raw file modified at correct section |
| QUERY | No file changes (read-only operation) |
| Preference/Goal statement | `logs/context/*.json` updated |

**Process:**
1. Capture file state BEFORE command
2. Run `uv run swealog run ...`
3. Check intermediate outputs in feedback JSON
4. **CRITICAL:** Verify file system changes match expected behavior
