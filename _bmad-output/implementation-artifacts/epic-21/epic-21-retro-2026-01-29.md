## Challenges and Issues

### 1. CORRECTION Merge Gap (Story 21.6 - HIGH)

**Problem:** Parser in correction mode outputs the literal user correction text instead of merging it with original entry content.

| Aspect | Actual | Expected |
|--------|--------|----------|
| Original | "Ran treadmill for 35 minutes at 8kph" | - |
| Correction | "actually it was 20 minutes at 7.5kph" | - |
| Result | "actually it was 20 minutes at 7.5kph" | "Ran treadmill for 20 minutes at 7.5kph" |

**Impact:** Corrected entries lose all context about activity type, equipment, notes.

**Root Cause:** Story 21.1 design told Parser to output "complete corrected section content" but didn't explicitly instruct it to MERGE with original.

**Resolution:** Story 21.6 created to fix Parser prompt with merge instructions and examples.

### 2. Entry Reference Format (Story 21.7 - LOW)

**Problem:** Synthesizer response references entries as "Entry 23, Entry 24, Entry 25" which is meaningless to users.

**User Feedback:** "what is entry 23, 24, and 25? it means nothing to user. needs actual reference on date and time."

**Resolution:** Story 21.7 created to fix Synthesizer (and possibly Analyzer) prompt to use dates.

## Key Learnings

1. **Prompt instructions need explicit merge behavior** - Saying "generate corrected content" is ambiguous; must specify "merge correction INTO original, preserving context"

2. **Internal references must be user-friendly** - Entry IDs and indexes are for code, not user-facing responses

3. **Real user feedback catches prompt gaps** - Automated tests verified mechanics but missed UX issues

4. **Reopening epics is acceptable** - Better to add hotfix stories to the right epic than mix concerns across epics

5. **Architectural changes can have prompt-level gaps** - Story 21.1-21.3 handled the code correctly; the gap was in LLM instructions
