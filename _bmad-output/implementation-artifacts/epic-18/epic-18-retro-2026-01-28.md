## Challenges and Issues

### 1. Story 18.2 Initial Implementation Gap
The initial Story 18.2 implementation printed formatted summaries instead of full JSON structures. User feedback in `2026-01-28_14b9034b.json` identified this gap:
> "I couldn't see intermediate outputs still. I only saw intermediate agent's response not whole json structure."

**Resolution:** Commit `50e6a8f` fixed this to print full JSON via `json.dumps(output, indent=2)`.

**Lesson:** "Debug output" needs clearer acceptance criteria - "formatted summary" vs "raw JSON" distinction should be explicit.

### 2. Code Review Caught Real Issues
Code reviews for Stories 18.1 and 18.3 found actionable issues:
- **Story 18.1:** Missing `ANALYSIS_FINDINGS: []` in error handler (inconsistent with success path)
- **Story 18.3:** Missing test for empty options list edge case

**Lesson:** Adversarial code review continues to add value, especially for error handling paths.

### 3. Two ClarificationQuestion Classes

- `quilto/models.py:14-30` - Public API (used by session.py)
- `quilto/agents/models.py:826-875` - Internal agent model

This wasn't a bug, but caused initial confusion. The state type annotation at `orchestration.py:199` is still wrong but fixing it was deferred to avoid scope creep.

## Key Learnings

1. **Fallback mechanisms build trust** - Synthesizer fallback in Story 18.1 means users never see "no data" when data exists. Graceful degradation > hard failure.

2. **Debug output scope matters** - "Print debug info" is ambiguous. Story 18.2 fix shows we need to specify: summary vs raw, which fields, format (JSON vs formatted).

3. **Type mismatches cross boundaries** - Story 18.3's bug (str vs dict) occurred because `PlannerOutput.clarify_questions: list[str]` passed through state to `session.py` which expected `list[dict]`. State type annotations should match actual data.

4. **Defensive isinstance() is cheap insurance** - Pattern from Story 17.4 applied successfully to Story 18.3. Cost is minimal, benefit is avoiding runtime crashes.

5. **Dogfooding works** - Stories 17.11 and 18.4 prove that iterative user testing finds issues that unit tests miss. The 80% → 100% success rate improvement validates this approach.

## Next Epic Preview

**Epic 19: Dogfooding Fixes & Design Issues**

Iter-007 and the retrospective session identified **2 bugs and 1 design issue** that require Epic 19 stories.

### Required Stories for Epic 19

#### Story 19.1: Fix CORRECTION input type flow (BUG - HIGH)

**Problem:** CORRECTION flow fails silently. Router correctly identifies CORRECTION (0.96 confidence) but Parser does not process the correction target.

**Evidence:** `tests/eval/feedback/active/2026-01-28_54959ede.json`
- Query: "I think I logged 5 sets yesterday but it should have been 4 sets of pull-ups"
- `correction.success: false`
- `correction.error_message: "Parser did not identify correction"`
- `final_response: ""` (empty - user got no feedback)

**Impact:** Users cannot correct previously logged data. The CORRECTION flow is non-functional.

**Investigation areas:**
- Parser agent's correction handling logic
- How correction_target from Router is passed to Parser
- Whether Parser has correction-specific prompts/instructions

#### Story 19.2: Fix session DB path default logic (DESIGN - MEDIUM)

**Problem:** The CLI defaults to `:memory:` for session DB when no `--session` flag is provided, making it impossible to retrieve sessions later.

**Evidence:** `packages/swealog/swealog/cli/app.py:319`
```python
session_db_path = "quilto_sessions.db" if session_id else ":memory:"
```

**Logical contradiction:**
1. No `--session` flag → `:memory:` → session created with UUID → **ephemeral, lost on exit**
2. With `--session <id>` → `quilto_sessions.db` → tries to load → **session was never persisted**

The only way to continue a session is if the first call also used `--session` with a manually-chosen ID, which defeats the purpose of auto-generated UUIDs.

**Fix:** Always default to `quilto_sessions.db` for persistence. Use `:memory:` only when explicitly requested (e.g., `--no-persist` flag or test mode).
