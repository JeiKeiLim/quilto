## Challenges and Issues

### 1. CORRECTION Flow Still Broken (Partially)
Story 19.1 fixed the code correctly, but Parser LLM doesn't comply. It returns `is_correction: false` despite correct prompts. Additionally, even when CORRECTION succeeds, the semantics are wrong - creates new entry instead of modifying existing raw file.

**Root Cause:** Prompt engineering issue + design mismatch. User expects: modify raw markdown in-place, re-parse, update parsed file.

### 2. Session Continuation Bug Discovered
Story 19.2 fixed **database persistence** (sessions saved to SQLite), but **conversation context** is not being used when resuming sessions.

**Evidence:** File `90c94c13` - User resumed with `--session <id>` but system didn't use previous conversation history. Query "What? You didn't look at my previous logs?" was treated as fresh start.

**Key Insight:** The Task 2.3 test ("What about last week?") was a false positive - that query is answerable without context. Real session continuation requires context-dependent queries.

### 3. Observer Fabricating Information
Observer stores Synthesizer recommendations as user preferences (Pattern 5) and hallucinates facts not in any entry (Pattern 9).

**User Feedback:** "Observer should only note something from me not from agents."

## Key Learnings

1. **Session persistence ≠ Session continuation** - Saving to SQLite is different from using conversation history in agents

2. **Test with context-dependent queries** - "What about last week?" is answerable without context. Real continuation tests need queries like "What? You didn't look at my previous logs?"

3. **CORRECTION semantics matter** - Creating new entries is wrong. Users expect: modify raw file in-place, preserve surrounding content, re-parse

4. **Observer scope must be restricted** - Only persist user-stated info (preferences, goals, insights), never agent recommendations or per-session facts

5. **Dual dogfooding is essential** - Automated tests + user manual testing catch different issues. User feedback with negative sentiment = high priority

6. **LLM prompt issues require different solutions** - Code fixes don't guarantee LLM compliance. May need prompt engineering, better context, or non-LLM heuristics
