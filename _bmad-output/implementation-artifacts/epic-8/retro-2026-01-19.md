## What Could Be Improved

### 1. Debug Verbosity Gap for Dogfooding (PRIMARY CONCERN)

**Observation:** The CLI provides application-level verbosity (user-friendly success/error messages), but for dogfooding Quilto development, debug-level verbosity is needed.

**User Feedback (Jongkuk Lim):**
> "manual_test.py was more helpful. I didn't know how to use swealog and it showed application level verbosity which is good in general but this phase, I was hoping more of debug level verbosity so that I would know what went wrong or well."

**Desired Behavior:** `--debug` flag that matches `manual_test.py` output:
- Which agent is running
- Agent inputs and outputs
- Which tool/method is being called
- Step-by-step flow through the pipeline
- Timing information

**Impact:** Primary user (developer dogfooding) cannot effectively debug framework issues through the CLI.

### 2. Recurring Edge Case Patterns

**Observation:** Code reviews caught similar issues across multiple stories:
- Timestamp/ID uniqueness assumptions
- Incomplete input type handling
- Missing error type coverage

**Recommendation:** Consider adding "Edge Cases Checklist" to story templates.

### 3. Local Model Limitations

**Observation:** Local qwen2.5:7b model:
- Works for unit tests and simple integration tests
- Struggles with full multi-agent pipeline flows
- Not viable for production use

**Insight from Jongkuk Lim:**
> "If we can make agents pass unit tests with local model, cloud-based model would perform better. That's the assumption."

**Value:** Local model serves as "hard mode" baseline for testing - robust prompts that work with limited models will excel with capable models.
